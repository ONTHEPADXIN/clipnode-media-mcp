# Privacy And Local Service

ClipNode Media MCP is designed for local, user-controlled media workflows. The MCP bridge connects an AI client to the ClipNode Android app local service, and the app performs media processing on the Android device.

## Local-First Model

ClipNode Media MCP does not render media in the MCP server. It sends task requests to the ClipNode Android app, and the app performs the actual media processing and export.

Typical flow:

```text
AI client
-> local MCP stdio server on the computer
-> ClipNode app local HTTP service on the phone
-> Android local media processing
-> optional download back to the computer
```

The local service is intended for trusted devices on the same local network.

## What Data May Be Accessed

Depending on the user's request and permissions, the workflow may access:

- Phone media directory names and file metadata.
- User-selected phone videos, images, GIFs, or audio files.
- Files uploaded from the computer to the ClipNode app.
- Exported outputs generated by the app.
- Task status, progress, warnings, errors, and event logs.

The AI client generally receives paths, metadata, task parameters, validation summaries, and progress states. It does not need the raw media bytes in the AI context to plan most tasks.

## Local Service URL And PIN

The ClipNode app shows:

```text
baseUrl = http://phone-ip:port
pin = app-generated PIN
```

The MCP server uses these values to connect to the app local service.

Security guidance:

- Keep the PIN private.
- Do not commit real PIN values to public repositories.
- Do not share screenshots that reveal the current PIN unless you intend to share access.
- If the PIN changes, update the MCP client config or call `clipnode_media_configure`.

## Network Safety

Do not expose the ClipNode local service to the public internet.

Recommended use:

- Same trusted Wi-Fi network.
- Personal hotspot or trusted LAN when needed.
- Firewall/router rules that keep the service local.

Avoid:

- Port forwarding the phone service to the internet.
- Publishing the service URL and PIN.
- Using the local service on an untrusted public network.
- Leaving long-running services exposed when not needed.

## AI Client Permissions

Different AI clients have different permission models. A connected client may be able to:

- Read local files that the client has access to.
- Upload files to the ClipNode app when the user requests it.
- Download exported results to local paths.
- Create media tasks using phone-visible file paths.

Review your AI client's file and network permissions. Only connect clients you trust.

## Media Permissions On Android

ClipNode may request media permissions so it can list, read, edit, export, and save user-selected media.

Depending on the feature, the app may need access to:

- Images.
- Videos.
- Audio.
- Local app output folders.

Permissions should be used for the related media workflow requested by the user.

## Uploaded Files And Outputs

Uploaded files may be temporary inputs or saved into the app asset library, depending on the request.

Outputs may remain available in the app output list until the user deletes or manages them. Use `clipnode_media_list_outputs` to list previous successful outputs when needed.

## Public Repository Hygiene

When publishing this MCP plugin or examples, do not commit:

- Real PIN values.
- Personal phone IP addresses if they identify your environment.
- Private media paths that reveal personal information.
- Expiring or authenticated m3u8 URLs.
- Cookies, tokens, auth headers, or private API keys.
- Large debug logs containing device names, paths, or media metadata.

Use placeholders:

```text
CLIPNODE_BASE_URL=http://192.168.1.23:8081
CLIPNODE_PIN=123456
/absolute/path/to/clipnode-media-mcp
```

## User Responsibility

Only use ClipNode Media MCP with devices, files, and networks you own or are allowed to access. Do not use it to access, edit, upload, download, or export another person's media without permission.

If you suspect the local service URL or PIN has been shared accidentally, stop the local service, regenerate credentials if available, and update your MCP client configuration.
